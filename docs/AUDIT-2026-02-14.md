## Findings by Severity

### Critical Issues

#### C1. Race Condition on Exclusive License Purchases
- **Location:** `app/api/checkout/route.ts:120`, `app/api/webhooks/stripe/route.ts:207`
- **Flow:** Customer
- **Description:** The exclusive license check at checkout validates `licenses_sold > 0`, but there is no atomic lock at the checkout validation step. Two concurrent checkout requests could both pass this check. The `process_track_purchase` RPC uses `FOR UPDATE` row locking, but if the RPC returns `success: false` (race lost), the order_items record is already created and the order is marked complete.
- **Impact:** Double-sold exclusives; customer pays but track status may be inconsistent; legal liability.
- **Fix:** Move the RPC call BEFORE creating order_items. If RPC fails, skip the item entirely and refund via Stripe. Add a unique constraint on `order_items(track_id)` where `license_type = 'exclusive'`.

#### C2. License PDF Generation Fails Silently
- **Location:** `app/api/webhooks/stripe/route.ts:247-251`
- **Flow:** Customer
- **Description:** If PDF generation throws, the catch block logs but continues. The order is already marked `completed`, the customer gets no license PDF, and no alert is sent.
- **Impact:** Customer pays but receives no license document; no admin visibility.
- **Fix:** Track PDF generation failures in a `failed_pdfs` queue or column. Send admin alert on failure. Add retry mechanism or manual regeneration endpoint.

#### C3. Floating-Point Precision in Earnings Calculation
- **Location:** `app/api/webhooks/stripe/route.ts:182`
- **Flow:** Customer / Creator
- **Description:** `item.price * (1 - discountPercent / 100) * revenueSplit` produces values like `$18.994300000000002` due to IEEE 754 floating-point arithmetic.
- **Impact:** Accumulated rounding errors in creator payouts over time.
- **Fix:** Use `Math.round(value * 100) / 100` at each multiplication step to maintain cent precision.

#### C4. Missing Price Validation at Checkout
- **Location:** `app/api/checkout/route.ts:157-164`
- **Flow:** Customer
- **Description:** Cart prices from the frontend are not compared against current DB prices. Stale or manipulated prices pass through to Stripe.
- **Impact:** Revenue loss; potential fraud vector.
- **Fix:** Compare each `item.price` against the DB price. Reject checkout if any price differs. Return which items have changed so the frontend can update.

#### C5. No Track Editing After Upload
- **Location:** Dashboard -- entirely missing
- **Flow:** Creator
- **Description:** Creators cannot correct mistakes, update pricing, change artwork, or modify metadata after submission. No edit page, no PATCH endpoint, no edit button.
- **Impact:** Major UX gap; creators stuck with errors forever.
- **Fix:** Build `/dashboard/tracks/[id]/edit` page + `PATCH /api/creators/me/tracks/[id]` endpoint with proper ownership validation.

#### C6. Rejection Reasons Not Displayed to Creators
- **Location:** `app/api/admin/tracks/[id]/reject/route.ts:45` + missing UI in TrackList
- **Flow:** Creator / Admin
- **Description:** Admin sets `rejection_reason` in the reject endpoint, but the field never appears in the creator dashboard.
- **Impact:** Creators cannot understand why tracks were rejected; cannot fix and resubmit.
- **Fix:** Show rejection reason in TrackList component. Add "View Details" modal for rejected tracks.

#### C7. `rejection_reason` Column Missing from Database
- **Location:** `app/api/admin/tracks/[id]/reject/route.ts:45` vs `supabase/migrations/20250126193600_initial_schema.sql`
- **Flow:** Admin
- **Description:** Code writes to `rejection_reason` but the column does not exist in the tracks table schema. Supabase silently ignores unknown columns.
- **Impact:** All rejection reasons are lost; the feature is completely broken.
- **Fix:** Add migration: `ALTER TABLE tracks ADD COLUMN rejection_reason TEXT;`

#### C8. Supabase Client Created Per Request in FastAPI (Never Cached)
- **Location:** `backend/app/routers/process.py:30-36`, `backend/app/routers/chat.py:157-164`
- **Flow:** Backend
- **Description:** `_get_supabase()` creates a new Supabase client on every single request. Clients hold DB connections that are never released.
- **Impact:** Connection pool exhaustion at scale; server crashes under load.
- **Fix:** Use `@lru_cache(maxsize=1)` or module-level singleton for the Supabase client.

#### C9. Temporary Files Never Deleted After Watermarking
- **Location:** `backend/app/routers/process.py:179-232`
- **Flow:** Backend
- **Description:** `watermark_audio()` creates a temp file via `tempfile.mkstemp()`. The `finally` block only deletes the input file, not the output. The output file is returned via `FileResponse` but never cleaned up.
- **Impact:** Disk space fills up over time; eventual server failure.
- **Fix:** Use `BackgroundTask` to delete output file after response is sent.

#### C10. No Structured Logging in FastAPI Backend
- **Location:** All backend files
- **Flow:** Backend
- **Description:** Only `print()` statements exist. No logging module, no log levels, no error tracking.
- **Impact:** Production blindness; cannot diagnose issues after deployment.
- **Fix:** Add Python `logging` module with structured JSON output. Consider Sentry integration.

#### C11. Open Redirect in Auth Callback
- **Location:** `app/(auth)/callback/route.ts:7,13`
- **Flow:** Infrastructure
- **Description:** The `next` query parameter is used directly in `NextResponse.redirect()` without validation. An attacker can craft a URL like `?next=//evil.com` to redirect users after login.
- **Impact:** Phishing attacks via crafted auth URLs.
- **Fix:** Validate that `next` starts with `/` and does not contain `//` or protocol prefixes.

### High Severity Issues

#### H1. Cart License Toggle Doesn't Update Price
- **Location:** `app/cart/page.tsx:247-251`
- **Flow:** Customer
- **Description:** Switching from non_exclusive to exclusive keeps the same price field. Customer sees non-exclusive price ($29) for an exclusive license.
- **Fix:** When toggling, fetch the correct price from track data or store both prices in cart item.

#### H2. Checkout Doesn't Verify All Cart Tracks Exist
- **Location:** `app/api/checkout/route.ts:87-97`
- **Flow:** Customer
- **Description:** Query fetches tracks by IDs but doesn't check `tracks.length === trackIds.length`. Deleted tracks are silently dropped.
- **Fix:** Compare lengths. Return error listing which tracks are no longer available.

#### H3. AI Search Returns Rejected/Pending Tracks
- **Location:** `app/search/page.tsx:127`
- **Flow:** Customer
- **Description:** After AI search returns track IDs, the Supabase query doesn't filter by `status = 'approved'`.
- **Fix:** Add `.eq('status', 'approved')` to the post-AI-search fetch.

#### H4. Stripe Metadata 500-Char Limit Overflow
- **Location:** `app/api/checkout/route.ts:233`
- **Flow:** Customer
- **Description:** `JSON.stringify(metadataItems)` can exceed Stripe's 500-char per-key limit with many cart items, causing silent truncation.
- **Fix:** Validate metadata length before creating session. For large carts, store items in DB and reference by order ID.

#### H5. Discount Calculation Duplicated Frontend/Backend
- **Location:** `stores/cartStore.ts:52` vs `app/api/checkout/route.ts:16`
- **Flow:** Customer
- **Description:** Identical discount logic exists in two places. No backend validation that the client-sent discount matches server calculation.
- **Fix:** Always recalculate discount on backend. Remove reliance on client-sent discount values.

#### H6. Dashboard Doesn't Check Creator Approval Status
- **Location:** `app/dashboard/layout.tsx:28-37`
- **Flow:** Creator
- **Description:** Only checks `is_creator` flag, not `creator.status === 'approved'`. Rejected or pending creators can access upload page.
- **Fix:** Fetch creator record and verify `status === 'approved'`. Redirect with message if not.

#### H7. `is_creator` Set Before Admin Approval
- **Location:** `app/api/creators/apply/route.ts:134`
- **Flow:** Creator
- **Description:** The flag `is_creator = true` is set on the profile when the application is submitted, not when approved.
- **Fix:** Only set `is_creator = true` when admin approves. Or keep it but add the approval status check (H6).

#### H8. No Concurrent Payout Request Protection
- **Location:** `app/api/creators/me/payout/route.ts`
- **Flow:** Creator
- **Description:** Double-clicking "Request Payout" can create duplicate payout records. No database lock or idempotency check.
- **Fix:** Use `SELECT ... FOR UPDATE` in a transaction, or add a `pending` payout check before creating new one.

#### H9. No Pagination on Admin List Pages
- **Location:** All `app/admin/` page files (submissions, creators, tracks, payouts, orders)
- **Flow:** Admin
- **Description:** All admin pages fetch ALL records with no `LIMIT`/`OFFSET`. Will break as data grows.
- **Fix:** Add server-side pagination with page/limit params. Add pagination UI component.

#### H10. License Limit Can Be Set Below `licenses_sold`
- **Location:** `app/api/admin/tracks/[id]/route.ts:125-129`
- **Flow:** Admin
- **Description:** Admin can update `license_limit` to any value, even below current `licenses_sold`, creating an impossible state.
- **Fix:** Validate `new_limit >= licenses_sold` before allowing update.

#### H11. No Email Failure Logging
- **Location:** Multiple admin endpoints (approve, reject routes)
- **Flow:** Admin
- **Description:** Email sending uses `.catch(() => {})` or no catch at all. Failures are completely invisible.
- **Fix:** Log email failures with recipient and context. Consider a retry queue.

#### H12. No Bulk Approve/Reject for Submissions
- **Location:** `app/admin/submissions/SubmissionsList.tsx`
- **Flow:** Admin
- **Description:** Only single-track operations. No checkbox selection or bulk actions.
- **Fix:** Add multi-select with bulk approve/reject actions.

#### H13. No File Size/MIME Validation on FastAPI Uploads
- **Location:** `backend/app/routers/process.py:82-174`
- **Flow:** Backend
- **Description:** No file size check, no MIME type validation. A 100GB upload will crash the server.
- **Fix:** Add `MAX_FILE_SIZE` check. Validate MIME type. Validate `preview_clip_start` range.

#### H14. `track_id` Not UUID-Validated (Path Traversal Risk)
- **Location:** `backend/app/routers/process.py:86`
- **Flow:** Backend
- **Description:** `track_id` is used directly in Supabase storage paths without format validation. A value like `../../etc/passwd` could manipulate paths.
- **Fix:** Validate with regex `^[a-f0-9-]{36}$` before use.

#### H15. API Keys Could Leak in Error Tracebacks
- **Location:** `backend/app/routers/chat.py:167-174`
- **Flow:** Backend
- **Description:** If `Anthropic()` or `create_client()` constructors fail, exception traces could expose API keys.
- **Fix:** Wrap client creation in try/except with generic error messages.

### Medium Severity Issues

#### M1. No Security Headers
- **Location:** Missing from entire codebase
- **Flow:** Infrastructure
- **Description:** No Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, or Strict-Transport-Security headers.
- **Fix:** Add headers in `next.config.js` or middleware.

#### M2. No Rate Limiting on Download Endpoint
- **Location:** `app/api/downloads/[trackId]/route.ts`
- **Flow:** Customer
- **Description:** Authenticated users can download files repeatedly with no throttling.
- **Fix:** Add rate limiting middleware (e.g., upstash/ratelimit).

#### M3. In-Memory Rate Limiter Doesn't Work Multi-Instance
- **Location:** `backend/app/routers/chat.py:75-98`
- **Flow:** Backend
- **Description:** Rate limiter state is in-memory. With multiple Uvicorn workers or servers, it's easily bypassed.
- **Fix:** Use Redis-backed rate limiting for production.

#### M4. No Audit Trail for Admin Actions
- **Location:** All admin endpoints
- **Flow:** Admin
- **Description:** No logging of who approved/rejected tracks, changed revenue splits, or processed payouts.
- **Fix:** Create `admin_audit_log` table. Log action, admin_id, target, timestamp.

#### M5. No Role-Based Admin Access Control
- **Location:** All admin endpoints
- **Flow:** Admin
- **Description:** All admins have identical permissions. A compromised account has full access.
- **Fix:** Add admin roles (super_admin, moderator) with scoped permissions.

#### M6. Homepage N+1 Queries
- **Location:** `app/page.tsx:216-252`
- **Flow:** Customer
- **Description:** Each homepage section makes a separate DB query for auto-fill tracks.
- **Fix:** Batch into a single query or use a server function.

#### M7. Homepage ISR Cache Serves Stale Sold-Out Status
- **Location:** `app/page.tsx:161` -- `revalidate = 300`
- **Flow:** Customer
- **Description:** 5-minute cache means exclusive tracks show as available up to 5 minutes after selling.
- **Fix:** Reduce revalidate time or use on-demand revalidation after purchases.

#### M8. Blocking I/O in Audio Processing
- **Location:** `backend/app/services/watermark.py`, `waveform.py`
- **Flow:** Backend
- **Description:** `pydub` and `librosa` operations block the event loop.
- **Fix:** Use `asyncio.to_thread()` for CPU-bound audio processing.

#### M9. No Timeout on Claude API Calls
- **Location:** `backend/app/routers/chat.py:270-308`
- **Flow:** Backend
- **Description:** If Claude API hangs, the request waits indefinitely.
- **Fix:** Add `timeout=30.0` to `anthropic.messages.create()`.

#### M10. Earnings Balance Calculation Duplicated
- **Location:** `app/dashboard/earnings/page.tsx:68-75` vs `app/api/creators/me/payout/route.ts:73-78`
- **Flow:** Creator
- **Description:** Same balance formula in two files. If one changes, they drift.
- **Fix:** Extract to a shared utility function.

#### M11. Creator Bio Not Sanitized for XSS
- **Location:** `app/creator/[id]/page.tsx:131-134`
- **Flow:** Creator
- **Description:** Bio renders raw text. No HTML escaping beyond React's default (which IS safe for text content, but not for dangerouslySetInnerHTML usage).
- **Fix:** Ensure bio is never rendered via `dangerouslySetInnerHTML`. Add DB-level length constraint.

#### M12. `deleted` Status in Frontend Doesn't Exist in DB
- **Location:** `app/dashboard/tracks/TrackList.tsx:40-44` vs migration schema
- **Flow:** Creator
- **Description:** `statusStyles` includes `deleted` but the DB enum only has `pending, approved, rejected, sold_out, removed`.
- **Fix:** Remove `deleted` from frontend styles or add to DB enum.

#### M13. Preview Clip Start Has No Max Validation
- **Location:** `app/dashboard/upload/page.tsx:877-889`
- **Flow:** Creator
- **Description:** No max value on clip start time input. Could exceed audio duration.
- **Fix:** Add `max` attribute based on audio duration or reasonable upper bound (3600).

#### M14. `/account/settings` Link Goes to 404
- **Location:** `app/account/page.tsx:107-116`
- **Flow:** Customer
- **Description:** Link points to `/account/settings` but the page exists at `/account/settings/` (check) or doesn't exist at all.
- **Fix:** Build the settings page or remove the link.

#### M15. No Resubmission Flow for Rejected Tracks
- **Location:** Creator dashboard
- **Flow:** Creator
- **Description:** Rejected tracks sit permanently in the track list with no action items.
- **Fix:** Add "Edit & Resubmit" option that sets status back to `pending` after edits.

#### M16. Audio Player Fails Silently on Network Errors
- **Location:** `components/player/AudioPlayer.tsx:81-85`
- **Flow:** Customer
- **Description:** If preview URL fails to load, playback pauses with no error UI.
- **Fix:** Add error state with toast notification.

#### M17. Account Settings Page Missing
- **Location:** `app/account/settings/`
- **Flow:** Customer
- **Description:** The settings page referenced in the account dashboard doesn't exist.
- **Fix:** Build basic settings page (name, email, password change).

#### M18. Weak Password Policy (6 chars minimum)
- **Location:** `app/(auth)/actions.ts:148-149`
- **Flow:** Infrastructure
- **Description:** Only 6 characters required. Below industry standard.
- **Fix:** Increase to 8+ characters minimum. Consider complexity requirements.
